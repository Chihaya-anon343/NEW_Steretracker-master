# 角点编号修复方案：Homography 候选与归一化模板验证

状态：已按用户后续限定，在单目 class0 的编号环节实现并完成测试，详见 [实现与实验报告](mono_corner_identity_20261016.md)。class1 新逻辑仅供独立实验、默认关闭，双目仍沿用原流程。本文保留原方案与离线分析记录；2026-10-16 已按用户确认的行序规则整理旋转模板文本编号。

## 1. 已确认的问题

本方案沿用 `corner_quality_20261016.md` 的数据与基线。class 0 BC 的 184 个对应偏移诊断帧中，174 个是纯循环移位，未发现纯反向遍历案例；其余 10 个含有非循环错配。class 1 的 118 个异常中，仅 25 个是纯循环移位，其余 93 个不能仅靠改起点解释。

`BinaryCornerExtractor::matchCorners()` 目前对模板和图像角点分别按 ROI 中心、模板角度加 20°选择起点，然后顺着轮廓配对。透视投影不保持图像中心、极角或距离排序，因此两个起点可能指向不同的物理角点。该过程没有验证整组对应是否满足同一个平面透视变换。

角度 IoU 模板只覆盖面内旋转，不完整描述透视形变。`approxPolyDP` 后强制补成十点的逻辑还可能在轮廓失真时引入非真实顶点，故返回十点不是编号可靠的充分条件。

普通 BC 随后生成 `DMatch(i,i)`，Dual-ROI 则直接按数组位置配对模型点。两处均依赖提取结果已经具有固定物理编号，这会把上游错位传播到 PnP。

### 旋转模板标签的特别说明

修复前，24 个旋转模板中有 18 个文件的 `Corner_N` 标签不按 0…9 顺序出现，这些历史标签不是跨角度一致的物理 ID。检查实际坐标后，文件行序与 0°模板的物理对应大体一致。

例如修复前的 90°模板，按现有行序与 0°模板拟合 H 的坐标残差约为 0；按旧标签排序后的残差约为 21.31 个模板像素。

用户已确认以行序为准。本轮已将每个文件第 i 个角点的标签改为 `Corner_i`；18 个文件发生标签变更，全部 24 个文件的坐标、行顺序和其余字节内容保持不变。核验记录：`output/template_label_fix_20261016/verification.json`。当前读取器只读取坐标，因此该整理不改变算法数值输入。最终实现仍应由标准模型定义物理编号，不在运行时按极角重新定义身份。

## 2. 离线可行性试验

脚本位于 `output/corner_quality_20261016/ordering_analysis.py`，读取原始实验已导出的 BC 点集，对闭合轮廓枚举十个起点与两个遍历方向，用全部十点拟合 H，并按拟合残差排序。模型使用现有 `0_degrees.txt`；每帧标注只在候选确定后用于评估，不参与选择。

以下为成功产生有限且无投影极点候选的子集，并非完整提取链重跑：

| 对象 | 样本数 | 原固定编号 P95 | 候选重排后 P95 | 原 RMSE | 重排后 RMSE | RMSE恶化超过1px的帧数 |
|---|---:|---:|---:|---:|---:|---:|
| class 0 BC | 930 | 624.29 px | 4.78 px | 237.12 px | 19.64 px | 5 |
| class 1 BC | 643 | 13.87 px | 10.40 px | 7.95 px | 4.86 px | 58 |

原完整可见有效输出分别为 932、645 帧；各有两帧未产生上述有效候选，应作为拒绝样本单列。不能用子集 P95 直接替换完整基线的 627.22 px。

结论：几何候选能修复大量 class 0 编号错位，但残余异常和 class 1 回退说明，仅按点拟合残差选 H 不足以作为正式修复。用户提出的归一化后图案验证适合作为第二层证据。

## 3. 推荐的正式流程

1. **保留现有前处理，取得闭合轮廓点。** 首阶段不同时修改阈值、形态学或亚像素算法，便于区分编号修复的收益。
2. **固定标准模型。** 使用 0°模型的固定物理编号，明确 class 0、class 1 的模型映射。旋转模板不再决定最终编号。现有物理尺寸、坐标原点、class 1 偏移和 30°先验沿用当前配置。
3. **生成候选对应。** 对十点轮廓枚举循环起点；先统一绕向，必要时检查两种绕向，总数最多二十。角度与凹凸结构用于粗筛或排序，不再单独决定身份。
4. **估计候选 H。** 由标准模板点到图像点拟合，用全部十点检查误差，并检查矩阵有限性、退化、投影极点和映射翻转。不允许仅取四个点拟合后，用这四点的接近零残差证明正确。
5. **投影归一化。** 使用 H 的逆变换，把实际 ROI 前景掩码及必要的灰度/梯度采样到固定标准平面，例如 128×128。变换图像有效区域掩码；出画面和边界填充区域不当作实测图案。
6. **独立图案验证。** 比较实际归一化前景与标准轮廓的 IoU、边缘距离或梯度一致性，结合点误差评分。优先验证前列候选；候选接近或未过质量门限时再扩展，最多检查全部候选。
7. **判断唯一性。** 最优候选必须同时满足绝对质量和相对次优候选的区分度。多个候选近似并列、轮廓不完整或分辨率不足时返回“对应不可信”，进入现有退化链，不强制选出一个编号。
8. **输出物理 ID。** 接受后按固定物理编号输出，或显式输出检测点到模型 ID 的映射。原始检测点、归一化图和评分保留在诊断信息中。

H 的方向明确为 `p_image ~ H_template_to_image * p_template`，归一化使用其逆变换。H 需要候选对应作为输入，不能先依赖当前未知编号求一个 H，再循环论证该编号正确。

归一化图必须来自实际图像或掩码。只把模板角点经 H 映射回原图得到的是模型预测，不是一次独立角点检测，也不能据此宣称检测误差已消失。

## 4. 链路兼容

| 链路 | 需要落实的规则 |
|---|---|
| 单目 BC / class1 BC | PnP 仅消费通过对应验证的 2D–3D 对 |
| 左图 BC + 右图 LK | 右点继承左点的物理 ID；光流筛选后保留 ID，不能按剩余点次序重新编号 |
| 左右独立 BC | 两侧都对应到同一标准模型 ID，再建立左右匹配 |
| Dual-ROI | 用 `(class_id, corner_id)` 查找模型点，避免重复按参考角重排；核对普通 BC 与 Dual-ROI 的规范编号映射 |
| 仅视差 | 左右对应的有效性与模板物理编号可信度分开处理；没有 PnP 时不应单因模板身份不确定丢弃有效左右观测 |
| 日志与可视化 | 显示物理 ID、候选数、点误差、归一化匹配分数、次优差距和拒绝原因 |

保持现有跟踪器公开函数入口；新增质量与身份诊断字段使用默认值。现有 PnP 正面/倾角约束继续保留，身份验证不能替代位姿二义性处理。

## 5. TT 的处理边界

四对点本来就可以确定一个 H，四点重投影误差不能有效验证其编号。TT 若采用同一框架，必须依靠归一化后的实际图案、边缘或可辨别的内部结构评分。

当前 TT 的 minAreaRect 是图像平面的矩形，大倾角下并不是靶板平面四个固定角点的投影。因此该框架可以先改善方向选择与质量拒绝，不能据此声称矩形模型偏差也被修复。建议先完成 BC，TT 后续单独验证。

## 6. 实施顺序与验收

1. 新建公共的平面轮廓对应模块，先接 BC；保留旧模式用于固定配置 A/B。
2. 同步核对单目、双目、光流、Dual-ROI、退化链的模型 ID 传递；添加日志和可视化。
3. 在相同的 1020 张图、相同 ROI 和配置上重跑 4080 次提取，分别统计有效输出、拒绝、固定编号误差、点集误差及对应偏移；同时报告小目标、大倾角、遮挡和出画面组。
4. 追加真实 YOLO ROI 的端到端实验，统计策略覆盖、失败、PnP 法向/深度跳变、正面约束通过情况与耗时。离线重排结果不能替代该步骤。
5. 单独检查原失败帧与原正确帧，防止通过大量拒绝换取更好 P95。阈值在独立验证片段上确定，并使用额外旋转/倾角边界样本检查泛化。

收益预期是消除大量循环错位、阻止不可信身份进入 PnP；无法从现有离线结果保证所有 class 1 帧改善或位姿跳变归零。修改规模为中等，集中在公共对应模块、BC 提取器、两类 Tracker 的映射消费及诊断测试。128×128 归一化和少量 H 候选有利于控制计算量，实际耗时必须在项目 Docker 工具链内测量。

## 7. 用户提出的 TT 四点归一化与四方向匹配

### 7.1 原候选方案的顺序澄清

候选是同一组十点的编号排列，不是任意组合的大量新角点。每组候选先估计自己的 H，再将实际图像归一化并验证，最后选出最佳可信的“编号＋H”。可以按点误差先筛选少数候选以减少图像变换，但不能先凭点误差最终定案，再只验证唯一一个 H。

### 7.2 TT 方案的可行部分

先取 TT 几何层的四个矩形顶点，建立一致循环顺序，归一化到固定大小正方形，然后比较标准图案的 0/90/180/270 四个方向。图案方向明确时，可快速获得朝向初值，再将 BC 十点变换到标准平面，建立固定编号并用十点重新估计更准确的 H。

完整候选链可作为该快速分支失败后的后备：

```text
前景轮廓 → 四点粗框 → 正方形归一化 → 四方向匹配
  ├─ 可信 → BC点初始编号 → 十点H精化 → 图案与几何复核 → 输出编号
  └─ 模糊/畸变大/复核失败 → 十点候选H方案 → 接受或退化
```

若用途仅为 TT 四点方向识别，可先独立评估四方向匹配；它本身不会自动生成 BC 的十个物理编号。

### 7.3 透视限制

当前 TT 四点来自 `minAreaRect`，是图像平面中的矩形。未精化的该矩形到正方形的变换本质上为旋转、平移与两个方向缩放，不包含真实目标透视的充分信息。角点经 `cornerSubPix` 偏离矩形后，数学上可能产生非仿射 H，但不能将这种局部偏移视为已测得真实板面四角。

板面上的真实正方形倾斜后通常投影成非矩形四边形；其最小外接矩形与原四角并非同一组物理点。因而 TT 方案可以改善粗方向判断，但在中大倾角、近距离或框选偏移下仍可能留有明显形变。30°总倾角约束有利于限制使用范围，但不能保证 minAreaRect 就是真实透视四边形。

### 7.4 工程注意事项

- 当前完整 TT 已在四点输出前进行 24 角度匹配，并在输出时按该角度旋转编号。新流程应取“尚未模板定向的几何四点”，避免沿用旧方向判断造成循环依赖。
- 大目标上不宜新增一次完整 TT ×4 放大链；复用已有前景掩码和轮廓计算 minAreaRect，再只生成一张低分辨率归一化图，四个方向可用精确 90°旋转比较。
- 统一以一个 0°标准图案派生四个方向，保证相同裁剪、边距与尺度。图案不对称且细节可辨时，四方向才有辨别力；分辨率太低、遮挡或清理后接近对称时，应通过分数差拒绝不确定方向。
- 对照实验需要分别比较原方案、TT四方向独立分支、完整候选H方案和两者组合；分别统计编号错误、拒绝率、像素误差、端到端位姿和耗时。现有 TT 实验数值不是新四方向流程的效果，不能直接沿用为收益结论。
