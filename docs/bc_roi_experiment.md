# ROI 光流金字塔实现与实验

方案 1 已实现，主配置与光流示例中 `stereo_frontend.roi_pyramid=true`。2026-10-12 的同条件 CPU 实测中，当前图对的光流匹配均值减少 **42.5%**，包含左 YOLO、灰度处理和 BC 的前端总耗时减少 **6.5%**。

## 实现

左右图采用同一个搜索区域。它覆盖左目标 ROI、左角点、配置允许的完整正视差范围和有效光流初值，再加入按窗口和最大金字塔层数计算的边界、NCC 窗口、垂直误差余量与额外 margin。原点对齐 `2^max_level` 网格，保持相对于全图金字塔的采样相位。

局部匹配将相机主点减去裁剪原点，重新计算局部极线；返回时恢复所有观测与诊断点的全图坐标。原角点编号、GPnP 输入、CSV 和可视化保持兼容。当前范围仅支持水平平行双目，一般旋转外参使用原全图实现。

区域面积达到全图的 85% 时直接全图；ROI 匹配未通过质量检查时默认重试全图。没有降低原有 FB、NCC、极线、视差、去重、数量及覆盖检查要求。回退结果采用全图检查结果，耗时包括两次尝试。

配置：`roi_pyramid` 默认 false；`roi_fallback_full` 默认 true；`roi_max_area_ratio` 默认 0.85；`roi_extra_margin_px` 默认 16。主配置与示例明确开启 ROI，其余配置默认值保留旧行为。设 `roi_pyramid=false` 可恢复全图金字塔。

核心改动位于 `StereoFlowMatcher` 的搜索区域推导、裁剪与坐标转换；配置、Tracker、日志增加调用参数和 ROI/回退信息。另新增独立合成实验并扩展现有前端基准。

## 实验设计

采用独立 Release 构建（GCC 11，`-O3 -DNDEBUG`），OpenCV 4.5.4。Docker CPU 可见 12 个逻辑并发，OpenCV 默认 12 线程，YOLO intra-op 4 线程。正式测量时没有同时运行构建或另一组基准。

**实验 A：当前图对前端对比。** 使用 1699×1744 的现有人工图对，左输入 `cj01_image_0032.jpg`，右输入 `cj01_image_0032 - 副本.jpg`。两条路径均仅左图 YOLO+BC，使用相同光流初值、质量阈值和输入，唯一切换项为全图/ROI 金字塔。PnP、可视化、磁盘输入输出和融合不计时。两批独立运行，每批每条路径预热 10 次、测量 100 次，交替执行顺序；合并各路径 200 个样本。

记录总前端、特征处理、匹配、金字塔、LK、裁剪的均值、中位数、P95，以及配对数量、视差中位数、ROI 像素面积和全图回退次数。子项耗时包含在父项中，不能重复求和。

**实验 B：真值场景。** 使用 1920×1080 的合成纹理图，右图由已知平移生成，包含普通匹配、300 px 大视差、需要粗搜索的冷启动、2 px 垂直偏移、45.5/1.25 px 亚像素位移、左右贴边、遮挡、空白右图和大区域直接全图共 10 类。垂直误差阈值明确配置为 3 px，其他质量阈值相同。每类每条路径预热 10 次、测量 50 次，交替执行顺序。

精度验收要求：接受点编号和成功状态一致；两条路径对应坐标差异小于 0.1 px；输出点对已知真值的误差小于 0.5 px。空白右图必须失败，禁止错误成功。实验失败返回非零退出码。

**回归测试。** `test_stereo_flow` 共 20 项通过，覆盖旧路径、ROI 坐标恢复、一般外参旁路、边缘、上下偏移、遮挡、大小视差、回退、GPnP 及仅视差模式的 CSV/可视化兼容性。主程序构建通过，当前配置运行通过。

## 实验 A 结果

| 阶段均值 | 全图金字塔 | ROI 金字塔 |
|---|---:|---:|
| 金字塔构建 | 12.25 ms | 6.29 ms |
| 光流匹配（包含裁剪与检查） | **12.77 ms** | **7.34 ms** |
| 灰度、裁剪、BC、匹配 | 25.77 ms | 17.18 ms |
| 总前端 | **142.87 ms** | **133.56 ms** |

| 延迟指标 | 全图 | ROI |
|---|---:|---:|
| 匹配中位数 | 11.72 ms | 6.96 ms |
| 匹配 P95 | 17.92 ms | 10.55 ms |
| 总前端中位数 | 139.10 ms | 131.89 ms |
| 总前端 P95 | 186.97 ms | 170.13 ms |

搜索区域为 1320×1048，1383360 / 2963056 像素，减少约 53.3%。ROI 裁剪及准备开销约 0.53 ms，已经计入匹配耗时。两路径均 200/200 次匹配通过，每次 10 对点，视差中位数约 45.0016 px；ROI 全图回退次数为 0。

两批总前端降幅为 4.34% 和 8.55%。YOLO 算法未改动，其耗时仍受机器负载波动影响，因此匹配子阶段的收益比总前端的收益更直接。

|---|---:|---:|---|
| 普通目标 | 9.21 ms | 2.81 ms | 两路径均 50/50 成功 |

| 上下偏移 2 px | 9.91 ms | 2.94 ms | 两路径均 50/50 成功 |
| 亚像素平移 | 10.17 ms | 3.21 ms | 两路径均 50/50 成功 |

## 适用范围和代价

当前普通 BC 测试图上收益成立。目标较小时裁剪收益更大，大目标时自动旁路。失败帧的全图重试会增加耗时：空白右图实验从 17.87 ms 增至 31.37 ms，约增加 75.5%。实际序列频繁失配时，整体收益可能减少，应结合回退率评估。

实验只覆盖当前 CPU 配置、人工图对和上述合成场景，不代表 GPU、真实连续序列的精度或完整系统 FPS；未改动目标物理尺度、标定或位姿质量阈值。
