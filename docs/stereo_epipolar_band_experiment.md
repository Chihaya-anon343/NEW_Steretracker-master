# BC 双目极线带优化与原版对照

2026-10-12 已实现极线带粗匹配，并在更新后的 `data/stereo_crop` 上完成 Docker Release 对照。每轮 60 对图，原单极线版本通过 **39/60**，最终极线带版本通过 **60/60**；三轮结果一致。平均匹配耗时 **19.65 → 4.60 ms**，降低 **76.6%**。成功帧视差 MAE 仍约 **0.009 px**。

本次只修改粗匹配搜索及其计算方式，没有引入帧间视差缓存。两种版本均使用左图 YOLO+BC、右图 LK；“原版”指修改前的单极线粗搜索光流版本，不是左右分别进行 YOLO+BC 的旧前端。

## 实现与配置

原版本最终允许 3 px 极线偏差，但粗 NCC 只扫描理想极线。当前人工右图有约 +1.774 px 垂直偏移，真实点在允许范围内，却没有被粗搜索直接覆盖。

修改内容：

1. 在极线法向 `±max_epipolar_error_px` 内搜索。当前 3 px 容差对应七条采样线；一般外参使用极线法向，而不是固定图像 Y 轴。
2. 左侧 NCC 窗口只归一化一次。每个沿线位置保留法向最佳候选，再按沿极线方向的距离检查独立峰的唯一性。
3. 水平平行双目且采样间距为 1 px 时，一次采样整条灰度带，用批量 NCC 和积分图计算相关系数、保留原弱纹理检查；其他情况使用逐点 NCC。
4. 初始沿线采样步长大于 1 px 时，对最多四个独立峰作有限局部精查，再交给 LK 做亚像素精化。

新增 `stereo_frontend.coarse_epipolar_band`，默认 true，主配置已显式开启。设置 false 可复现原单极线粗搜索；`coarse_retry=false` 关闭粗搜索。搜索次数上限及适用条件见 `docs/bc_stereo_flow.md`。

以下设置未放宽：LK 窗口 21、最大层级 3；FB 1 px；极线容差 3 px；NCC 下限 0.8、唯一性差值 0.03；正视差 0.5–400 px；至少 4 对、有效比例 0.6、空间覆盖比例 0.25。主流程仍使用同坐标初值，ROI 金字塔与全图回退机制保持原有语义。

## 数据与实验方法

- 60 对人工双目图，源目录 `上升image_00_间隔25`，视差从 10 增至 100 px。
- 正视差约定 `uL-uR=d>0`，右图固定约 +1.774 px 垂直偏移，光度扰动关闭，seed=42。
- 全部使用 normal+directory 同步批处理、仅视差模式；InitialPnP、GPnP 和位姿回退均跳过。manifest 真值只用于运行后的误差分析。
- 修改前先构建并保存原 Release 可执行程序，最终对照直接运行该程序；不是通过修改新代码的阈值模拟原版。
- 两个版本各先处理完整 60 帧预热，再分别重复三次全序列，按 A/B、B/A、A/B 顺序运行。性能组关闭可视化。
- OpenCV 4.5.4，CLion 项目 Docker 容器，CPU YOLO，同一模型与配置。计时为程序内部匹配阶段，包括 ROI 裁剪、金字塔、LK、粗搜索、检查及按需全图重试；不包括图像解码、YOLO、左 BC、PnP、文件输出和可视化。
- 实验前后核对全部 120 张输入图及 manifest 的 SHA256，数据未改变。

## 成功率与精度

点数按每轮统计。成功帧与失败帧的部分匹配分开计算。

| 指标 | 原单极线粗搜索 | 最终极线带粗搜索 |
|---|---:|---:|
| 每轮帧级通过 | 39/60（65%） | **60/60（100%）** |
| 三轮帧级通过 | 117/180 | **180/180** |
| 每轮全部保留点 | 435 | **598** |
| 每轮成功帧保留点 | 355 | **598** |
| 每轮失败帧部分保留点 | 80 | 0 |
| 每轮全图重试 | 21 | **0** |
| 成功帧视差 MAE | 0.009006 px | **0.009003 px** |
| 成功帧最大绝对视差误差 | 0.0259 px | 0.0363 px |
| 全部保留点垂直误差 MAE | 0.01067 px | 0.01125 px |

新版本恢复原先全部 21 个失败帧，原版接受的 435 对点全部保留，另增加 163 对。原有点的左坐标完全一致，导出右坐标最大差异约 0.001 px，包含 CSV 舍入影响。最大误差略增来自更大的保留点集合，不能仅用相近 MAE 推断每一个新增点都与原集合同样准确。

没有使用上一帧初值。第 29、60 帧另以 debug 模式单独启动，各重复处理两次：

| 冷启动图像 | 真视差 | 原版合格点 | 极线带合格点 | 极线带帧状态 |
|---|---:|---:|---:|---|
| 第 29 帧 | 53 px | 5/10 | **10/10** | 通过 |
| 第 60 帧 | 100 px | 2/10 | **10/10** | 通过 |

第 60 帧恢复点 NCC 约 0.993–0.998，FB 约 0.001–0.008 px，垂直偏移约 1.75–1.79 px；最终仍经过原质量门槛。

## 匹配阶段性能

均值与 P95 来自每种版本三轮共 180 个计时样本，不包括预热。P95 使用排序后的 nearest-rank 定义。

| 匹配阶段指标 | 原版 | 极线带 |
|---|---:|---:|
| 平均耗时 | 19.651 ms | **4.599 ms** |
| 中位数 | 12.629 ms | **5.217 ms** |
| P95 | 48.037 ms | **8.304 ms** |

平均耗时降低 **76.6%**，P95 降低 **82.7%**。各轮平均值：

| 轮次 | 原版 ms | 极线带 ms |
|---|---:|---:|
| 1 | 21.653 | 4.806 |
| 2 | 18.542 | 4.531 |
| 3 | 18.759 | 4.461 |

最初逐候选计算 NCC 的极线带实现虽然达到 60/60，但三轮平均匹配耗时约 25.93 ms，高于当轮原版约 18.50 ms；扩大搜索范围本身存在开销。最终增加批量 NCC 后重新执行上述独立对照，才获得表中的性能结果。初步实验保存在 `output/stereo_epipolar_band_test`，最终结果以 `output/stereo_epipolar_band_test_batched` 为准。

上述百分比只描述匹配阶段，不代表完整系统 FPS 同幅度提升。该数据由单张图生成，不能验证真实双目的深度或物理位姿精度，也不能保证真实遮挡、光度变化及重复纹理场景均为 100% 成功。

## 兼容性与验证

全部 **23 项**光流回归测试通过，新增覆盖正负亚像素垂直偏移、重复纹理唯一性拒绝、斜极线粗搜索，以及 ROI 冷启动上下偏移。现有 PnP、仅视差、负视差拒绝、失败处理、旧调用接口、模板原编号、CSV 和可视化测试继续通过。

- 关闭极线带开关后，60 帧状态、435 对点编号和导出坐标与保存的原版完全一致。
- 极线带 ROI 与全图都通过 60/60，接受相同的 598 对点，导出右坐标最大差异约 0.001 px。
- 三次重复运行中，各版本接受的点编号、导出坐标和帧状态均与自身预热运行一致。
- 每次 normal 批处理均左 YOLO 60 次、右 YOLO 0 次，PnP 耗时为零；位姿成功数为零符合仅视差模式约定。
- 保存全部 60 张 `stereo_fN.png`，并检查第 60 帧左右匹配图及逐点诊断面板；原文件命名与匹配点编号显示保持兼容。

## 复现与产物

```bash
bash scripts/docker-toolchain.sh cmake --build build-codex-bc-bench --target GPNP test_stereo_flow -j4
bash scripts/docker-toolchain.sh ./build-codex-bc-bench/tests/test_stereo_flow
bash scripts/docker-toolchain.sh python3 scripts/compare_stereo_epipolar_band.py --directory output/stereo_epipolar_band_test_batched --binary output/stereo_epipolar_band_test_batched/GPNP_band --repeats 3 --diagnostics
```

实验目录包含保存的 `GPNP_original`、`GPNP_band`，运行配置、源码与数据生成配置快照、图像与程序哈希、逐次日志及 CSV。

- `summary.json`：各次运行与三轮汇总；`frames.csv`、`points.csv`：逐帧与逐点结果，包含帧是否通过。
- `comparison.csv`、`consistency_checks.json`：原版兼容开关、共同点、ROI/全图及重复运行对照。
- `band_visual/stereo_f1.png` 至 `stereo_f60.png`：完整序列可视化。
- `diagnostic_original_f29/`、`diagnostic_band_f29/`、`diagnostic_original_f60/`、`diagnostic_band_f60/`：单对图冷启动的匹配图、逐点诊断与 CSV。

工程修改主要位于 `src/matching/StereoFlowMatcher.cpp`、配置类型与读取器、匹配诊断结构和 `tests/unit/test_stereo_flow.cpp`。追踪器对外函数接口、位姿路由和融合逻辑未因本次优化修改。
